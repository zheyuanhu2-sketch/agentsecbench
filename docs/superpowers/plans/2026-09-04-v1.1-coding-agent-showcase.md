# AgentSecBench v1.1 Coding-Agent Showcase Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add cross-platform reproducible evidence, a synthetic coding-agent threat catalog, and a
self-contained static benchmark report suitable for honest Codex for Open Source review.

**Architecture:** Preserve the frozen built-in v0.1 catalog and existing result contracts. Add a
separate external JSON catalog, render validated content-free artifacts through a small pure-Python
HTML renderer, and keep `scripts/showcase.py` as the sole atomic generator/checker for checked-in
showcase files.

**Tech Stack:** Python 3.11+, standard library only, pytest, Ruff, mypy, Git attributes, GitHub
Actions.

## Global Constraints

- Do not make live model calls or use credentials, network access, real repository data, or real
  vulnerability reports.
- Do not add runtime dependencies, a JavaScript framework, analytics, or remote report assets.
- Keep the v0.1 built-in catalog fingerprint
  `77b6e5ad903fc10f2b521e1951427c10bb061c9775c60878e6f7ecf642613311` unchanged.
- Keep generated JSON, Markdown, and HTML as exact LF-terminated UTF-8 bytes.
- Do not claim production-model security, users, downloads, contributors, or adoption without
  evidence.
- Do not publish a release or submit the OpenAI application as part of this plan.

---

## File structure

- Create `.gitattributes`: enforce LF for generated evidence, Python, JSON, Markdown, and workflow
  source that participates in byte-level checks.
- Create `examples/coding-agent-scenarios-v1.json`: ten synthetic scenarios, five normal/attack
  pairs, using the existing external catalog contract.
- Create `docs/CODING_AGENT_SCENARIOS.md`: threat coverage, exact catalog fingerprint, commands,
  and interpretation limits.
- Create `src/agentsecbench/report.py`: deterministic, escaped, content-free HTML renderer.
- Create `tests/test_repository_contract.py`: Git attribute regression contract.
- Create `tests/test_coding_agent_catalog.py`: external catalog shape, pairs, metrics, and fingerprint.
- Create `tests/test_report.py`: deterministic HTML, escaping, semantics, and redaction tests.
- Modify `scripts/showcase.py`: generate and verify `examples/showcase/index.html`.
- Modify `tests/test_showcase.py`: enforce the expanded generated file set and report boundaries.
- Modify `scripts/release_gate.py`: require the new source, documentation, tests, and report in the
  source distribution.
- Modify `README.md` and `CHANGELOG.md`: reviewer route and unreleased v1.1 record.

### Task 3: Deterministic static report renderer

**Files:**
- Create: `src/agentsecbench/report.py`
- Create: `tests/test_report.py`

**Interfaces:**
- Consumes: two validated `ResultArtifact` objects, a manifest mapping, and package version text.
- Produces: `render_showcase_html(unsafe, secure, manifest) -> bytes`.

- [ ] **Step 1: Write failing renderer tests**

Tests must assert two calls return identical UTF-8 bytes ending in one LF; the output contains a
`<!doctype html>`, one `main`, semantic tables with captions, visible metric labels, catalog and
artifact digests, a skip link, a viewport declaration, and a `prefers-reduced-motion` rule.

Pass an altered artifact identifier containing `<script>alert(1)</script>` through a dataclass
replacement and assert the raw tag is absent while `&lt;script&gt;` is present. Join the resulting
HTML bytes and assert absence of `SYNTHETIC-SECRET`, message bodies, file contents, tool arguments,
and remote `http://` or `https://` asset references.

- [ ] **Step 2: Run the focused tests and verify RED**

Run: `uv run pytest tests/test_report.py -q`

Expected: import failure because `agentsecbench.report` does not exist.

- [ ] **Step 3: Implement the pure renderer**

Implement `render_showcase_html` using only `html.escape`, deterministic ordered tuples, and a
single UTF-8 encoding boundary. Render metric percentages from the artifacts, identifiers and
status booleans from content-free task records, and digests from the manifest. Use embedded CSS,
system fonts, high-contrast light/dark colors, responsive grids, visible focus, and semantic HTML.

Reject mismatched catalog fingerprints, task selections, or malformed manifest artifact entries
with a dedicated `ReportError`. Do not read files or perform I/O in this module.
